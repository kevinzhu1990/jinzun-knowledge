# 旺店通员工操作手册

> 由《旺店通使用知识卡》确定性生成｜渲染版本 20260811.1｜源卡覆盖 60/60

## 1. 适用范围/版本边界

- 适用对象：客服、审单、运营、采购、管理五类岗位的新员工学习、上岗前演练与日常查错。
- 知识版本：2026-08-12.1；资料读取日：2026-08-12。
- 状态汇总：资料已验证 60 张；内部口径已核验 0 张；PENDING 0 张。
- 内容仅依据本次读取的旺店通语雀资料、用户提供的后台截图与金尊内部操作口径整理。
- 平台界面、订购价格、授权周期和退款规则可能变化；上线前应由对应岗位用当前后台复核。
- 资料未给出的视频号售后自动退款、京东平台侧售后策略等逐步配置均标记为 PENDING，不据此出正式操作题。

## 2. 系统结构（人/货/场/流量/转化）

- **人**：管理岗建账号并按最小权限授权；客服、审单、运营、采购各自只处理职责内流程，关键异常升级复核。
- **货**：平台货品先匹配系统货品，库存、库位、采购入库与退货入库共同决定可售数量和履约能力。
- **场**：淘宝/天猫、拼多多、京东、视频号、抖音、唯品会、阿里巴巴等店铺，经正确的平台类型和授权链路接入旺店通。
- **流量**：平台点击形成订单后，订单抓取、审核、库存占用和发货决定流量能否沉淀为有效成交。
- **转化**：审单准确率、缺货率、发货时效、售后解决率和利润报表共同反映成交质量，并指导下一轮货品与运营动作。

## 3. 点击→转化→复购反馈回路

平台点击/下单 → 审单岗核对并处理拆单与异常 → 库存占用/采购补货保障履约 → 仓内发货 → 客服完成退换货与顾虑化解 → 运营查看销售、发货、采购报表 → 调整货品、库存、渠道与服务 → 提升下一轮转化和复购。

闭环要求：每个岗位既要完成当前按钮动作，也要确认状态已流转、异常有记录、下游岗位能继续处理；只“点过按钮”不等于完成。

## 4. 关键杠杆点（1–3个）

1. **高｜审单与库存准确**：先解决货品匹配、库存占用、快递和异常拦截，再放行订单，直接降低错发、缺货和退款。
2. **高｜售后闭环速度**：退货入库、换货/补寄单和平台退款策略状态一致，减少顾客等待与二次投诉，保护复购。
3. **中｜报表反哺经营**：把销售利润、发货和采购数据按店铺/货品/供应商复盘，优先处理影响成交和毛利的1–3个问题。

## 5. 风险点

- **高**：强制审单、自动退款、店铺平台类型和高权限账号配置错误，可能造成错发、误退、绑店失败或越权操作。
- **高**：无效货品未匹配、库存同步任务未启用或退货状态未闭环，会让订单无法流转或库存失真。
- **中**：采购单未审核、入库数量/价格/良残属性未复核，会污染库存和成本数据。
- **中**：把日报数据当实时数据、只看销售额不看退款和成本，会导致错误经营判断。
- **管控规则**：所有 PENDING 卡必须先由对应岗位在当前旺店通及平台后台复核，再转为已验证并进入正式考核。

### 库存管理（6张）

#### WDT-K013｜启用库存占用前置能力

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：通用
- 学习目标：确保订单库存占用正常计算，避免所有订单被误判缺货。

**操作入口**

- 配置普通仓库 → 联系支持开启库存同步 → 联系技术支持开启定时任务

**操作前置**

- 当前业务适合单仓库存占用模式
- 普通仓库已配置

**操作步骤**

1. 确认使用单仓场景
2. 完成普通仓库配置
3. 由支持或研发开启库存同步
4. 由技术支持开启对应定时任务
5. 回到待审核验证库存标签

**完成标志**

- 待审核订单能按实际库存显示不缺货、部分缺货或全部缺货
- 不会出现全部订单无故显示缺货

**异常处理**

- 资料说明该库存占用方案适合单仓客户
- 只开库存同步但未开定时任务会导致全部订单显示缺货

**常见误区**

- 忽略单仓适用范围
- 只让支持开同步而漏开定时任务

**来源与依据**

- 来源 1：[库存占用—启用前置](https://zsxj.yuque.com/da3ftb/vgswhb/gnl6y7fuigc2v0nh)
- 主章节：库存占用—启用前置
- 操作依据：适合单仓；配置普通仓库后由支持开启库存同步，并由技术支持开启定时任务，否则订单均显示缺货。

#### WDT-K014｜理解库存占用优先级

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：通用
- 学习目标：理解库存不足时系统为何优先保留某些订单。

**操作入口**

- 订单 → 待审核 → 库存占用结果

**操作前置**

- 库存占用已正常启用

**操作步骤**

1. 先识别是否为预同步订单

**完成标志**

- 能解释订单占用顺序
- 不再只按列表显示顺序判断优先级

**异常处理**

- 人工抢占并审核可能改变原有占用结果

**常见误区**

- 只按付款早晚判断
- 忽略临近发货截止的订单

**来源与依据**

- 来源 1：[库存占用—优先级](https://zsxj.yuque.com/da3ftb/vgswhb/gnl6y7fuigc2v0nh)
- 主章节：库存占用—优先级
- 操作依据：订单优先级依次为预同步订单、临近发货截止时间、付款时间。

#### WDT-K015｜识别三类缺货标签

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：通用
- 学习目标：在待审核快速识别库存覆盖程度并分流处理。

**操作入口**

- 订单 → 待审核 → 库存标签

**操作前置**

- 库存占用正常运行

**操作步骤**

1. 查看订单库存标签
2. 区分不缺货、全部缺货、部分缺货
3. 部分缺货时查看缺货数量
4. 按库存状态决定审核或拆分

**完成标志**

- 所有商品数量都有缺口时识别为全部缺货
- 仅部分商品或部分数量不足时识别为部分缺货并显示数量

**异常处理**

- 订单审核、发货或退款后，部分缺货标记不再显示

**常见误区**

- 把一项缺货误判成全部缺货
- 订单状态变化后仍依赖旧缺货标签

**来源与依据**

- 来源 1：[库存占用—缺货标签](https://zsxj.yuque.com/da3ftb/vgswhb/gnl6y7fuigc2v0nh)
- 主章节：库存占用—缺货标签
- 操作依据：待审核显示不缺货、全部缺货、部分缺货；全量不足为全部缺货，部分不足会显示缺货数量。

#### WDT-K016｜处理不缺货与缺货订单

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：通用
- 学习目标：按库存状态选择普通审核、拆单或抢占，减少无序抢库存。

- 已核对库存标签和订单优先级

**异常处理**

**常见误区**

#### WDT-K018｜查询库存明细并维护默认库位

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：通用

### 售后自动退款（6张）

#### WDT-K032｜配置淘宝天猫入仓自动退款

> 状态：✅ 已验证（资料步骤已核对）

- 适用平台：天猫/淘宝
- 学习目标：让淘宝天猫退货在满足千牛策略并完整入仓后自动退款，降低误退和少件风险。

**操作入口**

- 千牛售后服务平台 → 策略中心 → 应用库 → 入仓自动退

**操作前置**

- 已在千牛店铺管理创建并实名售后子账号

- 已在 ERP 售后→售后管理→售后设置授权该子账号
- 已在千牛入仓自动退中新增策略并设置条件
- 策略已用案例验证后启用
- ERP 已设置对应自动退款

- 把可操作当成普通登录权限
- 为方便一次性给所有员工最高权限
